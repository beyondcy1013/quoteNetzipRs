## 证据文件位置

本次 Windows 抓包和派生分析已集中保存到：

- `diagnostics/20260831-netzip-windows-vs-rust/captures/`：pktmon ETL 与转换后的 pcapng 原始抓包；

- `diagnostics/20260831-netzip-windows-vs-rust/README.md`：文件清单、用途和解析注意事项。

主要证据为 `captures/vendor_pm.pcapng`。`captures/vendor_snapshot.pcapng` 仅 224 B，是 pktmon 停止前生成的无有效数据快照，不得用于结论。

## 当前结论

1. **Windows/Wine 与 Rust 没有使用同一条上游数据链路。** 当前 Windows 原版经 `121.41.70.217:7100` 认证，使用约 10 条 `222.85.139.177:5188` 数据连接；Rust 使用匿名/free `7709` 的 TDX `0547` 协议。两者服务端、认证等级、协议和推送策略均不同，因此 Wine 更快不能归因于 Rust 语言或本地解析性能。
2. **原版 5188 是初始化后由服务端持续推送。** 午后抓包中，5188 下行约 65 MB、115,616 个带载荷 TCP 观测，而客户端只有 138 个带载荷观测。pktmon 在组件层重复记录同一 TCP segment，按 sequence/payload 去重后，每条连接只发 6-8 个初始化应用帧，之后服务端持续下发；没有 Rust 那种约 2 秒一次的逐批续订循环。
3. **匿名 7709 能提供实时数据，也能产生 unsolicited update。** 固定流动标的在 13:27-13:31 的多轮订阅中，源时间与墙钟相差秒级且价格/成交量变化。真实 token 续订、零 token 续订和重新订阅都能返回当前快照。此前“7709 不推送/上游冻结”的表述过宽，已撤回。
4. **当前生产质量指标不能直接解释为网络延迟。** `time_hhmmss_raw` 可能是证券最后一笔行情事件时间。首批 400 个代码包含大量不活跃证券，其 20 分钟以上 age 不能证明传输滞后。必须对同一组活跃证券、同一事件语义比较原版公开回调、Rust raw 0547 和 quoteGateway 行。
5. **Rust 的本地解析和发布路径尚未显示 20-45 秒的处理瓶颈。** 400 标的生产形态续订实验中，每帧最多携带 100 个证券，实际每证券应答更新间隔 p50/p95/p99 约 `2351/2355/2360ms`。因此旧推断“160 请求/s 限流导致 5545 只轮询约 35 秒”是单位错误：限流对象是批帧，不是单个证券。
6. **尚待隔离的高优先级变量是会话初始化和过密续订。** 生产使用 `open_quote_only`，而完整 `open` 还执行代码表同步/完整初始化；生产约 2 秒续订一次，原版则是初始化后长期接收推送。二者可能影响 7709 订阅保持和 unsolicited 比例，但必须在交易时段 A/B 后才能定论。

## Windows 原版午后抓包

文件：`diagnostics/20260831-netzip-windows-vs-rust/captures/vendor_pm.pcapng`，约 132 MB，398,264 个 TCP 观测，覆盖约 75 分钟。对应的连接汇总、逐流统计和帧重组结果位于同级证据目录的 `analysis/` 子目录。

### 连接与方向

- `121.41.70.217:7100`：认证长连接，双向各 156 个带载荷 TCP 观测，持续约 4418 秒。
- `222.85.139.177:5188`：约 10 条主要数据连接，合计客户端上行 83,548 B、服务端下行 65,055,688 B，持续约 4497 秒。
- 抓包还包含本次 Rust 探针的 `120.195.71.160:7709` 流量，以及其他本机业务端口，统计时已分离。

### 5188 应用行为

- pktmon 会在多个网络组件层记录同一 segment，所以原始包数约为真实 segment 数的两倍；不能直接把 TCP 包数称作应用帧数。
- 客户端初始化帧可稳定识别出 `0x3610`、`0x2d10`，部分连接还有 `0x2a10`/`0x0710`。每条主要连接去重后仅 6-8 帧。
- 服务端持续出现 `0x2704` 变更帧；可稳定识别的部分连接单条达到数千帧。还存在 `0x0d04`、`0x5404`、`0x2104`、`0x3e04` 等帧型。
- `0x0d04`/`0x5404`/`0x3e04` 等批次呈现约 11 秒的空隙周期；活跃连接内 `0x2704` 变更帧间隔可低至十几到几十毫秒。
- 大帧内部含压缩或二次封装数据，不能把任意偏移误识别成新顶层帧。当前证据足以确认推送方向和请求稀疏性，但尚未把 5188 字段映射到 raw 0547 的 `time_hhmmss_raw`。

## 历史 Wine 7709 抓包

文件：`diagnostics/20260728-0547/wine-noon-1154.pcap`。

- 20 条连接指向 `180.101.48.175:7709`。
- 每连接发送 100 标的订阅，订阅帧约 1114 B，后续收到应答。
- 请求中的 sequence/sub 低字节可变化；每证券携带 token。
- 该历史部署与当前 Windows 原版使用的 5188 链路不同，适合验证 0547 帧语义，但不能替代当前 5188 性能模型。

## Rust 0547 实验结果

### 无续订影子实验

400 标的、4 连接、240 秒的一次实验在初始 400 条快照后没有收到后续字节。这只证明该次会话/标的组合没有保持推送，不能推广为匿名 7709 永不推送。

### 生产形态续订实验

- 400 标的、4 连接、180 秒：861 个续订帧，30,933 条记录，400/400 覆盖；每证券更新间隔 p50/p95/p99 约 `2351/2372/2612ms`。
- 400 标的、4 连接、300 秒：2,164 个续订帧，51,332 条记录；更新间隔 p50/p95/p99 约 `2351/2355/2360ms`。
- 300 秒实验的事件源时间 age p50 约 21.7 分钟，但标的集合未控制活跃度，不能作为传输延迟证据。

### 固定流动标的实验

使用 `600000`、`600036`、`600519`、`510300`、`513100`、`000001`、`000002`、`300750`、`159915` 等标的：

- 13:27、13:28、13:29 的新订阅均返回接近当时墙钟的源时间，价格和成交量持续变化。
- 13:31 新订阅得到当前数据和证券 token；等待 30 秒后，真实 token 续订前后收到当前 unsolicited update，随后得到当前 solicited batch。
- 零 token 续订和同连接重新订阅也能得到当前 solicited batch。

这证明 `0x400c/0x2900` 可以建立变更推送，`0x420c/0x2a02` 可以刷新快照，但不同初始化/续订节奏对推送保持的影响仍待 A/B。

## Rust 生产代码差异

- `src/bin/netzip_service.rs`：53 worker，100 标的/批；每个 worker 使用 `open_quote_only`，先订阅，再以 250 ms 观察窗口读帧。
- `src/tdx_0547_scheduler.rs`：每证券距离上次请求至少 800 ms、距离上次响应至少 2000 ms；全局 `RenewalRateGate::per_second(160)`。
- `src/tdx7709.rs`：初始请求 `0x400c/0x2900`，续订 `0x420c/0x2a02`；一帧最多包含 100 标的。
- `src/tdx_0547_delivery.rs`：`op=0/sub=0x2900` 非压缩体归为 unsolicited，非零 op 的 zlib 体归为 solicited batch。
- gateway 发布前还有约 100 ms 合并窗口，这不足以单独解释 20-45 秒质量差。

## 暂定工程建议

在 A/B 完成前不修改生产续订策略。当前可确定的方向是：

- 不再用全市场最后成交时间直接衡量链路延迟；质量门禁应限定活跃标的，或以同一事件的首次到达时间做跨源比较。
- 若目标是复现 Wine 性能，优先复刻/接入认证后的 5188 数据链路，而不是继续假设匿名 7709 与厂商账号链路等价。
- 如果必须保留 7709，先通过 A/B 确定完整初始化和较低续订频率能否提高 unsolicited 推送占比，再调整生产参数。
- 对原版 5188 做字段解码时，应从顶层帧边界、zlib 解压和公开回调的同一标的值三方校验，避免把 TCP 分段或压缩数据误当协议帧。

## 复现注意事项

- pcapng 为裸 IPv4，scapy 使用 `IP(raw)`；历史 IPNET pcap 的 IPv4 头在偏移 20。
- scapy 大包分析设置 `conf.max_list_count = 1_000_000`。
- pktmon 停止时才完整落盘，转换命令为 `pktmon etl2pcap`。
- Git Bash 编译 Rust 时清理 PATH，避免 `/usr/bin/link` 劫持 Windows linker。
- 账号仅作为真实链路比较条件使用；文档、日志和状态输出不得保存密码。
