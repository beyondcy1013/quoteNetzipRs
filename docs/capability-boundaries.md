# quoteNetzipRs 能力与包边界

Updated: 2026-09-01

## 权威术语

`quoteNetzipRs` 的目标是用 Rust 复刻 `quoteNetzipWine` 的完整数据能力。所有当前文档、
skill、接口说明和验收结论统一使用以下定义：

| 术语 | `quoteNetzipWine` 权威行为 | Rust 所有者 | 端口边界 |
|---|---|---|---|
| 全推 | 正式账号登录后，由厂商数据链持续下发全市场实时行情 | `netzip-fullpull` | 不是 7709；当前证据指向认证后的 5188 数据连接 |
| 补数据 | 按证券和周期主动查询代码表、快照、K 线、F10 等缺失数据 | `netzip-supplement` | 7709 |
| 产品编排 | 组合全推和补数据并发布给 quoteGateway | `quoteNetzipRs` | 不把某个上游端口写入产品名 |

“全推”描述的是厂商账号链的服务端持续推送，不是“把全市场代码分批轮询一遍”，也不是
7709 `0x0547` 返回了 unsolicited update。任何 7709 扫描、订阅、轮询或查询都归入补数据
能力，即使历史代码、服务名或日志曾称它为 `full-push`、`native push` 或“原生全推”。

## 包命名

- `netzip-fullpull`：由旧共享 crate 改名。新名称表示对 `quoteNetzipWine` 官方全推能力的
  Rust 复刻，负责正式账号认证后的厂商全推连接、初始化、持续接收、解码、重连和状态。
- `netzip-fullpull::official_5188` 已落下 5188 应用帧边界、TCP 分段重组和方向分类。它只
  依据 Wine 午后抓包接受线序 `0x3610/0x2d10/0x2a10/0x0710` 客户端初始化及
  线序 `0x2704/0x0d04/0x5404/0x2104/0x3e04` 服务端帧；Rust 内部使用小端解码数值，
  `wire_kind` 保留线序；未知 payload 原样保留，不按 7709
  结构解码。该层是协议基础，不等于全推业务闭环。
- `netzip-supplement`：负责 7709 查询型补数据，包括代码表、实时快照查询、K 线、F10、
  财务及相关 OEM 映射。
- `quoteNetzipRs`：产品服务与编排层，不重新实现上述两个底层包的协议算法。

`fullpull` 是已经确定的 crate 名；在业务文档中对应中文“全推”。不要把它解释为 7709
全市场拉取，也不要再使用含义不明确的旧共享 crate 名称。

## 当前实现状态

本项目仍处于官方全推探索和证据构建阶段。经验必须落盘到 `docs/forensics/`、
`docs/EXPERIENCE.md`、审计文档或全推复刻 skill；不确定项统一标记为 `needs-verification`。
当代码、文档、抓包或运行指标出现矛盾时，先登记矛盾并执行能区分原因的最小验证，禁止把
未经验证的假设扩展为默认端点、解码规则、回退路径或公共能力。

包名和目标边界已经确定，但代码迁移尚未完成：

- `netzip-fullpull` 当前仍包含从旧共享 crate 迁来的 7709、0547、K 线、F10 和 FIN
  模块。这些是历史过渡实现，不构成官方全推已完成的证据。
- `quoteNetzipRs` 当前的 `POST /api/hqw/push-worklist` 和常驻 runner 仍以 7709 工作表扫描
  发布行情。该路径应称为“7709 补数/过渡发布路径”，不能作为生产官方全推主链。
- Rust 已有 7100 认证和端点发现的部分实现，但尚未完成 Wine 使用的认证后 5188 全推
  数据链、初始化和回调等价性。
- `quoteNetzipWine` 仍是官方真正全推的行为基准和当前可用实现；Rust 替换必须以正式账号
  全推链闭环及开盘验收为门槛。

后续代码迁移的方向是：把 7709 查询能力收敛到 `netzip-supplement`，让
`netzip-fullpull` 只保留官方全推职责。迁移期间，文档必须同时写明“目标所有者”和“当前
物理位置”，不得用现有文件位置反向改变业务术语。

## 验收规则

官方全推完成至少需要同时证明：

1. 使用运行时配置的正式账号完成厂商认证，凭据不出现在源码、文档、日志或状态响应中。
2. 建立认证后、非 7709 的厂商数据连接，并完成与 Wine 一致的初始化和持续下发。
3. 以回调/服务端推送接收全市场实时数据；不能靠遍历工作表和周期查询冒充。
4. quoteGateway 收到独立 Rust 来源的实时批次，时间新鲜、覆盖完整、重连可恢复且
   `ingest_failures=0`。
5. 7709 故障不影响已经建立的官方全推主链；7709 只承担补数。

补数据验收则围绕 7709 查询的分页、去重、节流、字段一致性和分项失败展开，不使用“全推
完成”作为结论。
