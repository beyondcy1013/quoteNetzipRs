# 1522 / 7100 认证取证包（只读信息文档）

本目录是为"用纯 Rust 复现真实账号 1522 的 7100 认证"而收集的证据集。
**它只汇总已知的静态/离线证据与抓包结论，不修改任何 Rust 协议代码，不运行实时登录。**

生成日期：2026-08-06
证据来源：`Z:\quoteNetzipRs` 仓库现有抓包/转储/Rust 解析器，以及在
`D:\Soft\_Stock\飞狐2020\` 对 `网际风.exe` / `Stock.dll` / `系统\Stockdrv.dll` 的静态取证。

## 一句话现状

- **已经能复现的**：第 1 包（611B 标准压缩 `认证|请求=登录` 帧）可用账号/密码动态生成，
  且 `examples/auth_7100_login.rs` 已能用环境变量凭据完成一次 `121.41.70.217:7100`
  的三响序列登录（`zstd_dictionary -> download_file -> zstd_dictionary`）。
- **阻塞纯 Rust 复现的根因**：第 2/3 包（271B / 333B）和加密服务端应答（443B / 395B）
  是 `penc + ZSTD字典(field44=12) + Tdx_Encrypt` 壳，标准 `zstd` 解压会报
  `Data corruption detected`，**这条可逆链尚未还原**。当前 Rust 实现只能把抓到的 271/333 字节
  作为硬编码 replay 发出（`src/auth_7100_client.rs:12-13`），无法为新会话生成。
- **二进制侧已确认**：`Tdx_Encrypt`、`penc`、`hypenc`、`ZSTD` 都是
  `Stock.dll` / `网际风.exe` 内的真实字符串，不是抓包猜测。`Stock.dll` 仅导出
  `Start / Stop / Ask` 三个函数，`Tdx_Encrypt` 是内部符号。

## 安全约束（适用于本目录所有后续取证工作）

1. **密码绝不落盘/落日志/落聊天**：真实账号 1522 的密码只能以环境变量
   `NETZIP_TDX_PASSWORD` 临时传入被测进程；不得写入源码、截图、pcap 命名、
   提交信息、聊天内容或普通临时文件。
2. **不要在生产 Wine 运行期间反复登录**，避免踢掉现有行情会话；实时抓包应在
   独立窗口/独立测试目录、与生产错峰进行。
3. **抓包文件只保留脱敏副本**：原始 pcap 在独立目录完成分析后，用 `editcap` /
   脚本抹除密码区，只保留长度/偏移/哈希，再交付。
4. **不改 Linux 生产服务、不替换 Rust 二进制**：本包是只读信息收集。
5. **每个结论必须带可复核证据**：时间戳、进程 PID、连接四元组、原始帧偏移、文件 SHA-256。

## 工作顺序建议（来自原始需求）

最有价值的取证顺序是：

1. 先抓一次成功登录的完整时序（见 `protocol_timeline.md` 模板）；
2. 再定位 DLL 内"明文登录体 → 最终网络帧"的边界（见 `forensic_brief.md` §D）；
3. 最后才分析加密算法与最小 Rust 实现（见 `crypto_transform_notes.md` 结论）。

不要只交付"抓包文件"。真正需要的是"抓包 + 调用链 + 字段偏移 + 成功/失败对照"，
只有这样才能判断 1522 是否能被纯 Rust 安全复现，而不是把账号配置进去却仍走未认证的 7709。
