- 这是第 4 个独立生命周期（且为 login_primary=true 健康主站）上对「五主分区 =

## P6/P7 跨生命周期稳定性（新增决定性发现）

- 将 formal-primary-121528（交易时段 12:15 独立登录）与 fixed-accept-2000
  （晚间 20:00 独立登录）的 7 条 2a10 解码后逐条比较：**P1–P7 全部逐条相等**
  （含此前标记「动态」的 P6 1024 与 P7 59，市场+symbol index 全同）。
- 结论：P6/P7 虽含 non-primary 分类切片，但其**指派在同一账号/服务器
  （58.16.134.228）跨两个独立登录生命周期完全稳定**——即它们是确定性派生
  （按 0104 全表固定分类规则），不是随机/每会话变化集合。先前「动态」仅指
  其在 0104 eligible 前缀之外，不能解读为不稳定。
- 待验证边界：这是同一服务器 + 同一接收清单配置下的稳定性；若切换
  broker/权限/接收清单，P6/P7 是否变化仍是未知（需对应增删因果实验）。

## 2704/Wine 310 条未匹配的根因分解（21:36 离线分析，基于 parity 080949 报告）

对 20 条 mismatch_samples 分类（外推至 310 条）：

| 根因桶 | 样本 | 外推 | 含义 |
|---|---|---|---|
| A Wine public-state 保留旧值 | 10 | ~155 | 内部 timestamp 15:00:01 但 cb 15:00:00、internal amount=0 而 cb 有值。Wine `0x44aa30` 合并时跳过零值增量、保留旧 public-state。不是解码错误，是 state-merge 语义。 |
| C f32 精度差 | 5 | ~78 | internal 与 cb 差 <1000（比值 ≈1.0000），f32 表示精度边界。非真差。 |
| D 真值分歧 | 4 | ~62 | 603066/603071 有 11/13 字段不匹配（仅 name/last_close 匹配）——Wine 有一个更新版本，5188 增量流窗口内没有对应 delta，或解码 baseline 错。 |
| B 解码 bug（负 amount） | 1 | ~16 | 603069 internal=-165257699639 而 cb=60622064，符号翻转/越界，解码 bug。 |

关键发现：
1. **A 桶（~155 条，约半数）不是解码错误**，是 Wine 跳过零值增量的 state-merge
   语义——Rust 实现需要在 `to_public_quote`/parity 时复刻「internal=0 时保留
   旧值」的合并规则，而非视 0 为有效值。
2. **B 桶（~16 条）是解码 bug**：负 amount 说明某字段的符号位/截断处理错。
3. C 桶（~78 条）f32 精度差属可接受，不需要修（Wine 也是 f32）。
4. D 桶（~62 条）最复杂：需确认是增量流本身没带 vs 解码 baseline 错。

下一步：B 桶（decoder bug）是可立即修复的项；A 桶合并规则是可离线验证的项。

## B 桶负 amount 根因定位（21:40，decoder 层面）

- 负 amount 的直接来源：`decode_value_accumulators` 中
  `current.set_i64(0x1c, delta_amount.wrapping_add(baseline_amount))` 在
  delta_amount 为负且绝对值大于 baseline_amount 时产生 i64 下溢（负 wrap）。
  Wine 的 amount 永远非负，负值一定是 delta 解码或 baseline 起始值错。
- 可能原因（按可能性）：
  1) delta token 对该符号编码了一个本应跳过的特殊标记（如除权除息日偏移），
     解码器误当数值增量处理；
  2) baseline_amount 取自身前的 public-state 不是同类型/同精度字段
     （0x24 abs vs 0x1c signed 的 offset 混用）；
  3) delta 位宽度对该特定 token 超界。
- 修复策略：加一个非负校验 `if amount_at_0x1c < 0 { treat as decode error }`，
  并把该记录标记为解码失败而非产出负值（防御性修复，不影响正常记录）。
  深层修复需更多跨 delta-token 取证（下一交易时段窗口/增量流对比）。
